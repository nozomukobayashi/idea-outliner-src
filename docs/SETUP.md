# 使い方

## 準備（チームで 1 回）

1. ノートを置くリポジトリ（アイディア用リポジトリ）を作ります。例: `your-team/ideas`
   - 見られる人がそのままノートの閲覧者になります。社内では internal での公開をおすすめします
2. リポジトリの **Settings → General → Features** で **Discussions** を有効にします
3. Discussions の画面で、プロジェクトやテーマごとにカテゴリを作ります
   - 有効にすると Ideas や General などが自動で作られるので、そのまま使っても構いません
   - Announcements は管理者しか投稿できません

## トークンを作る（各自 1 回）

GitHub / GHE の右上のアイコン → **Settings → Developer settings → Personal access tokens** で発行します。

**Fine-grained token**（使える場合はこちらをおすすめします）

- **Resource owner**: リポジトリの owner を選ぶ。**組織のリポジトリなら、自分ではなくその組織を選びます**
- Repository access: アイディア用リポジトリと、Issue を作るリポジトリを選ぶ
- Repository permissions: **Discussions** と **Issues** を Read and write、**Metadata** を Read-only

1 つの fine-grained token で扱えるのは 1 つの owner の配下だけです。組織によっては承認が必要だったり、使用が禁止されていたりします。

**Classic token**（次のような場合）

- GHES で fine-grained token が使えない
- 組織が fine-grained token を許可していない、または internal のリポジトリを使う
- ノートと Issue の作成先が別の owner にある

`repo` にチェックを入れます。自分が触れるリポジトリすべてに効く強い権限なので、有効期限を短めにしてください。

トークンは接続先の API 以外には送られません。既定ではタブを開いている間だけ保持します。再読み込みでは消えず、タブを閉じると消えます。「このブラウザに保存する」を選ぶと、そのブラウザの localStorage に保存されます。消すときは「接続を管理」→「トークンを削除」を使います。

GHE Pages で使っている場合は、同じ GHE の他の Pages サイトと保存領域を共有するため、「このブラウザに保存する」は出ません。ブラウザのパスワード保存や 1Password に登録しておくと、タブを開き直したときに自動で入力できます。アプリを開いたタブで、そのまま他の人の Pages に移動しないでください。

## 接続する

1. アプリの URL を開きます
2. 接続先（github.com なら空欄）とトークンを入力して「接続」を押します
3. ワークスペース（アイディア用リポジトリ）を選びます

## ノートを書く

左の「＋ 新規ノート」で作ります。行をクリックすると編集できます。

| 操作 | キー |
|---|---|
| 行を追加・分割 | Enter |
| インデント / 戻す | Tab / Shift+Tab |
| 並べ替え | Alt+↑ / ↓ |
| TODO に切り替え | Ctrl(⌘)+Enter、または行頭に `[ ] ` と入力 |
| 空の行の削除、前の行との連結 | 行頭で Backspace |
| 保存 | 自動（入力が止まって 3 秒後）、または Ctrl(⌘)+S |

### 同時に編集したとき

別の人が同時に編集していても、違う行の変更は自動で統合されます。同じ行を変えていた場合は、どちらを残すか選ぶ画面が出ます。

本文は GitHub の Discussion の画面からも編集できます。行の末尾の `<!-- id:xxxx -->` は、行を見分けるためのものなので消さないでください。

## Issue にする

行にマウスを乗せて「Issue にする」を押し、作成先のリポジトリを選びます。子の行は Issue の本文にリストとして入ります。親の行がすでに Issue なら、サブイシューとして紐づけます。

作成すると、行の末尾に `owner/repo#番号` が追記され、Open / Closed が色で表示されます。

既存の Issue を参照するときは、行の中で `owner/` と打つとリポジトリ、`owner/repo#` と打つとその Issue が候補に出ます。番号や題名の一部で絞り込み、↑↓ で選んで Enter か Tab で確定します。

ノートの先頭のコメントに `defaultRepo` を書いておくと、作成先の初期値になります。

```markdown
<!-- idea-outliner:v1 {"defaultRepo":"your-team/web"} -->
```

## 議論する

行の「コメント」を押すと、右側にその行の議論が開きます。コメントは Discussion のコメントとして保存されるので、アプリを使わない人も GitHub の画面で読めます。

返信、コメントの編集・削除は GitHub の画面で行ってください。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「トークンが無効か期限切れです」 | トークンを作り直して「接続を管理」から入れ直す |
| リポジトリが候補に出ない | Discussions が有効か。入力欄に owner だけ入れて探すと出るか |
| 「見つからないか、このトークンではアクセスできません」 | ブラウザでそのリポジトリを開けるなら、トークンの問題。fine-grained token の Resource owner と対象リポジトリを確認するか、classic token（`repo`）で試す |
| 読み取り専用で開く | そのリポジトリへの書き込み権限があるか |
| Issue のチップが「取得できません」 | Issue のリポジトリがトークンの対象に含まれているか |
| 「API に接続できませんでした」 | ネットワークと接続先のホスト名。社内環境なら GHE 管理者に CORS の設定を確認する |
